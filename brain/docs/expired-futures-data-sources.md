# Alternatives to Upstox for 1-Minute OHLCV+OI on Expired NSE NIFTY Futures (Nov 2024 → Mar 2026)

**As of:** 2026-07-11. **Scope:** data sources/APIs that can plausibly serve **1-minute OHLCV + open interest** history for **expired** NSE NIFTY 50 index futures contracts, for the window 2024-11 → 2026-03.

**Research method:** WebSearch + WebFetch against primary sources — official API developer docs, official pricing pages, official support/FAQ pages, and each vendor's own community/support forum (which several vendors use as their de-facto changelog/Q&A channel — treated here as vendor-official when the reply is from a staff/moderator account, and flagged when it's a community member instead). Third-party sites (Kaggle, blogs, unofficial "XTrader" tools) are flagged explicitly as non-primary and lower-reliability. Every claim below has a URL; where no primary source could be read, that is stated explicitly rather than presented as confirmed. This mirrors the citation discipline used in `brain/docs/futures-cost-schedule-research.md`.

## 2. Per-source detail

### 2.0 Groww Trade API — CONFIRMED, BEST DOCUMENTED ALTERNATIVE FOUND

*(Added 2026-07-11 in a follow-up pass — the user holds a Groww account, so this was investigated with the same rigor as the rest.)*

- **Two distinct historical-data products exist, and the distinction is critical:**
  1. **Legacy "Historical Data" endpoint** (`GET /v1/historical/candle/range`) — per direct fetch of https://groww.in/trade-api/docs/curl/historical-data: 1-min candles limited to **"Last 3 months"** lookback (7 days per request), response contains **only** `timestamp, open, high, low, close, volume` — **no OI** — and the page itself carries a deprecation notice: this endpoint "is deprecated and will NOT work in the future," directing users to the Backtesting endpoint. **On its own, this endpoint is a dead end for the ask.**
  2. **Backtesting APIs** (launched **2025-10-03** per the official changelog, https://groww.in/trade-api/docs/curl/changelog, fetched directly: "Historical Data APIs launched with comprehensive historical market data from 2020 onwards… Expiries API and Contracts API specifically designed for derivatives backtesting") — per direct fetch of https://groww.in/trade-api/docs/curl/backtesting:
     - **Get Expiries**: takes `exchange`, `underlying_symbol`, optional `year`/`month` — returns available (including past) expiry dates.
     - **Get Contracts**: takes `exchange`, `underlying_symbol`, `expiry_date` — returns the contract symbols for that expiry as Groww symbols. This is a designed **expired-contract discovery mechanism**, structurally equivalent to Upstox's Get Expired Future Contracts API.
     - **Get Historical Candle Data**: fetches OHLC candles for the resolved symbol; docs state candles include **"Open Interest (OI) for FNO"** as the **7th array element** (null for non-FNO), intervals **1min through 1month** (minute-level capped at ~30 days per request), and — decisively — **"Data of FNO instruments are available from 2020."**
     - Stated limitation: "Currently, Backtesting APIs only support CASH and FNO segments" — NIFTY index futures (NFO/FNO) are in scope.
- **Coverage verdict:** "from 2020" fully covers Nov 2024 → Mar 2026 with ~4 years of headroom — deeper than Upstox's community-reported ~2024-10-03 floor by roughly four years, if the doc claim holds in practice.
- **Cost/auth:** per direct fetch of https://groww.in/trade-api: Trading API subscription is **"₹499 Per month plus taxes" (Early Bird Offer)** against a **regular price of "₹2000 Per month plus taxes"**; "Anyone with a Groww account" can subscribe (no minimum funding requirement stated). Auth is Bearer access-token + `X-API-VERSION: 1.0` header (per the historical-data doc page). Secondary corroboration of the ₹499 figure and single-subscription bundling: https://www.marketcalls.in/fintech/groww-enters-the-algo-arena-with-powerful-trading-apis.html and https://www.chittorgarh.com/broker/groww/api-for-algo-trading-review/173/ (both secondary, flagged as such).
- **Not fully verified:** (a) the groww.in/trade-api pricing page's module list says "Historical Data (up to 3 months)" — wording that predates/omits the Oct-2025 Backtesting product — so **whether the Backtesting APIs are included in the same ₹499 subscription was not explicitly printed anywhere read this session** (the changelog records no separate pricing, and secondary sources describe one all-inclusive subscription, so inclusion is the reasonable inference, but it is an inference); (b) no independent community post was found yet confirming non-empty 1-min+OI bars actually return for a specific expired NIFTY futures contract — the product is only ~9 months old and forum coverage is thin. Recommend a cheap hands-on test (₹499, self-serve) before committing.
- **Verdict: confirmed from official docs on all four axes the task cares about (expired-contract mechanism, 1-min interval, OI, window coverage) — the strongest alternative to Upstox found in this research pass.**

### 2.1 Zerodha Kite Connect — CONFIRMED DEAD END for 1-min expired data

- Official docs list supported intervals as `minute, day, 3minute, 5minute, 10minute, 15minute, 30minute, 60minute`, and describe `continuous=1` as the mechanism to reach expired NFO/MCX futures contracts by reusing a live contract's `instrument_token`. Source: https://kite.trade/docs/connect/v3/historical/ (fetched directly).
- Official Zerodha support article confirms the `continuous` chart feature is the access method for expired **futures** (not options) — https://support.zerodha.com/category/trading-and-markets/charts-and-orders/charts/articles/historical-data-for-expired-f-o-contract (fetched directly; the page itself doesn't state interval limits).
- **Confirmed restriction:** a Zerodha staff account ("rakeshr") on the official Kite Connect developer forum states explicitly: *"You can get day candles data, for an expired contract not minute level data."* Source: https://kite.trade/forum/discussion/4369/how-to-get-historical-data-for-expired-futures-by-minute-level-candles (fetched directly). This matches the task's stated "established belief" and multiple independent forum threads found via search (e.g. https://kite.trade/forum/discussion/12133/invalid-interval-for-continuous-data — "Continuous works only for interval = day").
- OI availability specifically for the continuous/expired path was **not stated explicitly** in the threads read; the general historical-data `oi` flag is documented (https://kite.trade/docs/connect/v3/historical/), but since minute intervals aren't reachable for expired contracts at all, the OI question is moot for this use case.
- **Verdict: dead end.** Even with `oi=1`, only day-granularity is available for anything past expiry.

### 2.2 AngelOne SmartAPI — CONFIRMED DEAD END

- Official SmartAPI docs / release notes list supported intervals for `getCandleData` (ONE_MINUTE through ONE_DAY) with per-interval max-days limits (e.g. ONE_MINUTE: 30 days per request, 8000-record cap). Source: search-derived summary of https://smartapi.angelone.in/smartapi/forum/topic/4012/release-note-free-historical-data-access-for-indices-nse-nfo-bse-bfo-mcx-and-cds-with-smartapi (fetched directly).
- **OI: officially not supported at all**, for live or expired data. A moderator states: *"This API does not provide Open Interest info for now"* (noted as "under consideration" for the future). Same source as above.
- **Expired F&O: officially not supported.** A moderator states plainly: *"We do not provide historical data of expired F&O contracts as of now."* Same source, fetched directly.
- This is corroborated independently in a separate forum thread (https://smartapi.angelone.in/smartapi/forum/topic/5395/nifty-futures-historical-data, fetched directly) where a user complains the historical API "can provide only data of live F&O contracts, not the expired ones" and AngelOne staff does not dispute it.
- **Verdict: dead end on both axes (expired contracts AND open interest).**

### 2.3 Fyers API — CONFIRMED DEAD END

- Official Fyers support article on viewing expired contracts confirms Fyers does **not** show historical/expired option-chain or candle data once a contract expires — the contract is simply removed from the trading screen, and users are directed to NSE's own reports for expired-contract history. Source: https://support.fyers.in/portal/en/kb/articles/can-i-view-expired-contracts-in-fyers (fetched directly).
- Community corroboration: users report the History API "sends no data when called with options/futures that expired before certain dates," and the fyers.in community explicitly contrasts this with Dhan/Upstox already supporting expired-contract data. Sources: https://fyers.in/community/fyers-api-rha0riqv/post/how-to-fetch-previously-expired-options-candle-data-CFa1C569E0pTBs4, https://fyers.in/community/questions-5gz5j8db/post/historical-f-o-data-h1D2iTTDCKfm5es (both found via WebSearch, not independently re-fetched — flagged as community corroboration, not a re-verified primary read of each thread).
- **Verdict: dead end**, and Fyers' own support content implicitly acknowledges the gap by pointing users elsewhere (NSE).

### 2.4 DhanHQ API — CONFIRMED DEAD END for futures (options-only expired support)

- Official docs show two historical-data families: the general `/charts/historical` (daily) and `/charts/intraday` (1/5/15/25/60-min) endpoints — these do **not** cover expired contracts, per docs and per staff confirmation below. Source: https://dhanhq.co/docs/v2/historical-data/ (fetched directly).
- A **separate, dedicated** "Expired Options Data" endpoint exists — but per direct fetch of its docs, it is scoped to **index options and stock options only** (`OPTIDX` and stock options; parameters include strike price and option type CALL/PUT), with no mention of futures. It does support 1/5/15/25/60-min intervals, OI, IV, and up to 5 years of history at 90-day-per-call increments. Source: https://dhanhq.co/docs/v2/expired-options-data/ (fetched directly).
- **Direct, official confirmation that expired futures are out of scope:** on Dhan's own community forum (MadeForTrade — used by Dhan staff for support), a user asks specifically about historical BankNifty **futures** data across expired monthly contracts; Dhan staff member **Trishul_Devadiga** replies: *"we don't provide expired contracts data,"* offering only a workaround of using the always-current near-month contract for **daily** granularity (continuous data back to 2011) — intraday/minute data is explicitly limited to the last ~3 months while a contract is live. Source: https://madefortrade.in/t/how-to-get-historical-futures-data-through-data-api/35207 (fetched directly).
- **Verdict: dead end for futures.** The Expired Options Data product is real and reasonably strong (5yr, 1-min, OI) but categorically does not cover NIFTY index futures.

### 2.5 ICICI Direct Breeze API — UNVERIFIED / PROMISING BUT UNCONFIRMED

- Official Breeze API docs (`GetHistoricalChartsList`) list intervals as `1minute, 5minute, 30minute, 1day`, and the sample JSON response schema includes an `open_interest` field (populated `None` in the equity example shown, structure otherwise present). Source: https://api.icicidirect.com/breezeapi/documents/index.html (fetched directly).
- The docs state that for `product_type` values other than `cash`/`btst` (i.e., for futures/options), `expiry_date`, `right`, and `strike_price` become **required**, with `expiry_date` in `DD-MMM-YYYY` format — implying the API is designed to target a specific (potentially past) expiry, not just the current live one. Source: same page, plus example code cited via https://www.icicidirect.com/futures-and-options/api/breeze/article/how-to-download-historical-data-using-breezeapi-python-sdk (WebSearch-derived, not independently re-fetched).
- Official ICICI Direct FAQ states: *"Historical data helps traders do a scenario analysis... Breeze API offers 3 years of historical data for Futures and Options... at no cost."* Source: https://www.icicidirect.com/faqs/fno/is-there-availability-of-f-o-historical-data-with-breeze-api (fetched directly). This FAQ does **not** explicitly say "including expired contracts," nor does it explicitly confirm OI populates for real futures queries (only the schema, with a `None` example, was seen).
- **What's missing to fully confirm:** an explicit statement (docs or corroborating forum post) that querying a **past** `expiry_date` on an NFO futures instrument actually returns non-empty 1-minute bars with populated OI, as opposed to erroring out like Fyers/AngelOne do for past expiries. No such statement or corroborating community post was found in this research pass.
- **Verdict: the most promising broker-API candidate that is NOT yet confirmed** — recommend a direct hands-on API test (free, no extra cost) before relying on it.

### 2.8 GlobalDataFeed (GDFL) — PARTIALLY CONFIRMED, retention vs backfill distinction matters

## 3. Shortlist — ranked alternatives to Upstox

*(Re-ranked 2026-07-11 after the Groww follow-up pass; Groww displaced TrueData at #1.)*

1. **Groww Trade API** — decisive fact: it is the **only broker API besides Upstox whose official docs confirm all four requirements at once** — a designed expired-contract flow (Get Expiries → Get Contracts by past `expiry_date`), 1-min interval, OI in the candle response, and FNO coverage "available from 2020" (≈4 years deeper than Upstox's community-reported ~Oct-2024 floor) — self-serve at ₹499/mo+tax early-bird, and the user already holds a Groww account. (https://groww.in/trade-api/docs/curl/backtesting). Gap: no independent community confirmation yet that expired NIFTY futures actually return non-empty bars; cheap to test directly.

2. **TrueData** — decisive fact: an **official TrueData staff reply on their own support forum** states NSE futures contract-wise data is available at **1-minute granularity from June 2015 to date** — the deepest explicitly-dated per-contract 1-minute coverage claim in this survey, unambiguously spanning Nov 2024 → Mar 2026. (https://feedback.truedata.in/topic/38617-best-plan-for-historical-data-for-nifty-fn). Gap: OI-at-1-min not explicitly confirmed; pricing requires a sales email.

3. **ICICI Direct Breeze API** — decisive fact: the only **free** broker API whose official docs both list a `1minute` interval AND include an `open_interest` field in the historical-data response schema AND require an `expiry_date` parameter for NFO (implying past-expiry targeting is a designed use case). Gap: no explicit doc statement or forum post confirms non-empty data actually returns for a genuinely past expiry — needs a live test.

(GDFL's purchasable backfill drops to honorable mention: it is the only vendor with an officially-stated backfill-purchase product beyond its ~3-month live retention, but nothing about its date range, OI inclusion, or price could be confirmed without a sales inquiry.)

(Stolo would likely rank #1 or #2 if its claims could be verified — 4 years, 1-min, futures+options, NSE-authorised OI — but it is excluded from the ranked shortlist because its own site was unreachable in this session and every claim about it is second-hand via search snippets, not a primary read.)

## 4. Confirmed dead ends

- **Zerodha Kite Connect** — `continuous=1` is day-interval only for expired futures; official Zerodha staff forum reply confirms no minute-level data exists for expired contracts, period.
- **AngelOne SmartAPI** — official moderator statement: no expired F&O historical data at all, and no OI data at all (even for live contracts).
- **Fyers API** — official support content confirms expired contracts are removed from the platform with no historical candle access; users are pointed to NSE directly instead.
- **DhanHQ (for futures specifically)** — official Dhan staff forum reply: "we don't provide expired contracts data" for futures; the one expired-data endpoint that does exist (Expired Options Data) is scoped to options only, not futures.
- **StockMojo** — confirmed options-only, no futures coverage at all.
- **OpenAlgo** — not a data source in its own right; strictly inherits the (dead-end) limitations of whichever broker is plugged in.
